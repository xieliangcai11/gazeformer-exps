# 数据是怎么一步步走进模型的？

> 这篇文章是给完全不懂编程的人看的。我会尽量用大白话，把"你的数据集"到"模型算出结果"的每一步讲清楚。不懂的专业词我会当场解释。

---

## 一、先记住一句话

**你的模型吃的不是图片文件本身，而是"已经处理成数字的小块图片"。**

就像做菜：菜市场买来的整棵白菜（原始图片）不能直接下锅，要先洗、切、摆盘（预处理），才能端上桌给客人（模型）吃。

下面我们就从"菜市场"走到"餐桌"。

---

## 二、整条路的地图

先给你一张总图，心里有个底，后面再一步步走：

```
【第1步】 图片文件夹 + 标签文件
              │
              ▼
【第2步】 读取标签文件，知道"每一行对应哪张图、真值是什么"
              │
              ▼
【第3步】 按标签去磁盘读图片，转成"数字块"（张量）
              │
              ▼
【第4步】 把数字块打包成一摞一摞（batch），送进模型
              │
              ▼
【第5步】 模型算出猜测的视线方向
              │
              ▼
【第6步】 拿猜测和真值比一比，算出"差多少"，用来学习
```

下面每一步详细讲。

---

## 三、第 1 步：数据集长什么样

你的数据在 `data/Gaze360/GazeHub/` 文件夹里，分两个大块：

```
data/Gaze360/GazeHub/
├── Image/          ← 图片
│   ├── train/Face/1.jpg
│   ├── train/Left/1.jpg
│   └── train/Right/1.jpg
│   ...
└── Label/
    ├── train.label  ← 标签（一份"说明书"）
    └── ...
```

**Image（图片）**：真的照片，一张张裁好的脸。

**Label（标签）**：一份文本说明书，每一行说"第几号图片，人往哪里看"。

举个例子，打开 `train.label` 你会看到这样一行：

```
train/Face/7371.jpg train/Left/7371.jpg train/Right/7371.jpg rec_001/head/000000/001620.jpg 0.6258,-0.3859,-0.6778  0.7455,-0.3962
```

别怕，这一行翻译成人话就是：

| 位置 | 内容 | 人话 |
|---|---|---|
| 第1块 | `train/Face/7371.jpg` | 这张脸的照片放在哪 |
| 第2块 | `train/Left/7371.jpg` | 左眼的照片放哪 |
| 第3块 | `train/Right/7371.jpg` | 右眼的照片放哪 |
| 第4块 | `rec_001/head/...` | 原始大图的出处（溯源用） |
| 第5块 | `0.6258,-0.3859,-0.6778` | **3D 视线方向**（人往哪看，3 个数） |
| 第6块 | `0.7455,-0.3962` | **2D 角度**（yaw 左右、pitch 上下） |

这一行就是"标准答案"。模型的任务就是看着这张脸，猜出这 3 个（或 2 个）数字。

> 专业术语：这一行叫"一个样本"（sample），第5块叫"标签/真值"（label / ground truth）。

## 四、第 2 步：代码读取标签文件

这一步在 `train.py` 里，负责"读说明书、准备一个大名单"。

看代码（`train.py:184-186`）：

```python
train_label_file = TRAIN_LABELS_PATH / "train.label"
val_label_file   = TRAIN_LABELS_PATH / "val.label"
test_label_file  = TEST_LABELS_PATH  / "test.label"
```

它去 `Label` 文件夹里找三份说明书：`train.label`（训练）、`val.label`（验证）、`test.label`（测试）。

然后（`train.py:190-194`）为每一份说明书，建一个"数据集对象"（ZhaoDataset）：

```python
train_ds = ZhaoDataset(train_images_path, [train_label_file], TRAIN_DATASET_NAME)
val_ds   = ZhaoDataset(val_images_path,   [val_label_file],   TRAIN_DATASET_NAME)
test_ds  = ZhaoDataset(test_images_path,  [test_label_file],  TEST_DATASET_NAME ...)
```

**这个"数据集对象"是什么？** 你可以把它想象成一本"菜谱目录"：

- 它知道一共多少道菜（样本数 `__len__`）
- 它知道每一道菜怎么做：根据第几号，去磁盘读哪张图、对应的真值是什么（`__getitem__`）

**此刻还一张图都没读**，只是建好了"目录"。真正读图在下一步。

## 五、第 3 步：读图片，变成数字块（最核心的一步）

这是整条链路里最关键、也最容易懵的一步。分两小层。

### 第 3.1 层：包装壳 ZhaoDataset

`ZhaoDataset`（`train.py:44-67`）本身不干活，它是个"皮包公司"，把活转包给底层真正的数据集类 `DatasetEyeDiapByGazeHub`（Gaze360 用的就是它）。

```python
class ZhaoDataset(Dataset):
    def __getitem__(self, idx):
        _input, label = self.inner_dataset[idx]   # ← 转包给底层
        return _input, label
```

所以真正的"读图"逻辑在 `gazehub_datasets.py` 的 `DatasetEyeDiapByGazeHub.__getitem__` 里。

### 第 3.2 层：真正的读图 + 转数字

看 `gazehub_datasets.py:147-158`：

```python
def __getitem__(self, idx):
    face_img = cv2.imread(self.images_path / self.labels[idx].Face)  # ①读图片
    face_img = cv2.cvtColor(face_img, cv2.COLOR_BGR2RGB)             # ②换颜色顺序
    face_img = Image.fromarray(face_img)                             # ③转成 PIL 格式
    other_face_img = copy.deepcopy(face_img)                         # ④复制一份

    face_img       = self.transform(face_img)                        # ⑤A 处理：喂给 CLIP
    other_face_img = self.other_transform(other_face_img)            # ⑤B 处理：喂给 CNN

    label = self.target_transform(self.labels[idx]._3DGaze)          # ⑥取真值

    return edict(face=face_img, other_face=other_face_img), label    # ⑦交出
```

逐句翻译：

- **① 读图片**：按说明书第1块给的路径，去磁盘把 `train/Face/7371.jpg` 这张图片读进内存。此刻它是"一张照片"。
- **② 换颜色顺序**：OpenCV 读进来颜色是 BGR（蓝绿红），但模型习惯 RGB（红绿蓝），所以要换一下，否则颜色会错乱。
- **③ 转格式**：换个工具库能识别的格式（PIL）。相当于同一张照片换个查看器打开。
- **④ 复制一份**：`copy.deepcopy`。**同一个图复制成两份**：`face_img` 和 `other_face_img`。它们内容一样，但接下来会走不同的"加工流水线"。
- **⑤ 加工**：两份图分别套用不同的变换。
- **⑥ 取真值**：把说明书第5块那 3 个数拿出来当标准答案。
- **⑦ 交货**：一份包装里装三样东西——`face`（给 CLIP 看的）、`other_face`（给 CNN 看的）、`label`（标准答案）。

### 第 3.3 层：两份加工（transform）是什么

为什么同一张图要复制两份、走不同加工？因为两个"厨师"口味不同。

看 `config.py:63-69`：

```python
CLIP_MODEL, CLIP_PREPROCESS = clip.load("ViT-B/32", device=DEVICE)
# 这份是给 CNN 的
CNN_PREPROCESS = transforms.Compose([
    transforms.ToTensor(),                                            # 转成数字块
    transforms.Normalize(mean=[0.485,0.456,0.406],                    # 归一化
                         std=[0.229,0.224,0.225]),
])
```

以及 `gazehub_datasets.py:88-96` 里给 CLIP 的那份（`__transform`，用于 `other_face`... 注意命名容易晕，见下面备注）：

```python
__transform = transforms.Compose([
    transforms.RandomResizedCrop(224, scale=(0.8, 1.0)),   # 随机裁剪缩放
    transforms.RandomHorizontalFlip(),                     # 随机左右翻转
    transforms.ColorJitter(brightness=0.2, contrast=0.2, saturation=0.2, hue=0.1),  # 随机调色
    transforms.ToTensor(),                                 # 转成数字块
    transforms.Normalize([0.5,0.5,0.5],[0.5,0.5,0.5]),     # 归一化
])
```

> **命名备注（怕你晕）**：在 `ZhaoDataset`（`train.py:60-61`）里，传给 `transform` 的是 `CLIP_PREPROCESS`，传给 `other_transform` 的是 `CNN_PREPROCESS`。所以实际上 `face` 用的是 CLIP 的预处理（`CLIP_PREPROCESS`），`other_face` 用的是 CNN 的预处理（`CNN_PREPROCESS`）。底层类的 `__transform` 只是"兜底默认值"，因为上层传了参数，就用上层传的。

**"转成数字块"（ToTensor）是什么？** 一张照片本质上是一个网格，每个格子是一个颜色值。ToTensor 把这张网格变成一个"数字立方体"：

- 彩色图 = 3 层（红、绿、蓝）
- 每层是一张 224×224 的网格
- 所以变成 `3 × 224 × 224` 的数字块

**"归一化"（Normalize）是什么？** 把每个格子的数字从"0~255"这种大数字，缩到"0 附近的小数"，让模型学起来更稳。就像做菜前把食材切成统一大小，方便下锅。

> 专业术语：这个"数字立方体"叫**张量**（tensor），形状写成 `[3, 224, 224]`。这是模型的"通用语言"。

### 第 3.4 层：那些归一化数字（0.485、0.229...）是哪来的？准不准？

你看到 `Normalize(mean=[0.485,0.456,0.406], std=[0.229,0.224,0.225])` 一定会疑惑：这些神秘数字是瞎写的吗？**不是，它们有明确出处，而且非常准。**

**先说结论：这套数字来自 ImageNet 数据集的统计结果，是全行业通用的"标准配方"。**

**这些数字分别是什么？**

- `mean`（平均值）是 3 个数：`[0.485, 0.456, 0.406]`——分别对应图片的**红、绿、蓝**三层的"平均亮度"。
- `std`（标准差）是 3 个数：`[0.229, 0.224, 0.225]`——分别对应三层的"亮度波动范围"。

**它们是怎么算出来的？**

有人把 ImageNet（一个有 1400 万张图片的大数据集）里所有图片的像素值统计了一遍：

- 算所有红色像素的平均值 → 0.485（红色整体偏暗一点）
- 算所有绿色像素的平均值 → 0.456
- 算所有蓝色像素的平均值 → 0.406（蓝色最暗）
- 再算各颜色的"波动幅度"（标准差）→ 0.229 / 0.224 / 0.225

**它们为什么准确？** 因为：

1. **源自真实数据**：不是拍脑袋，是从海量真实图片统计出来的。
2. **是"约定俗成"的标准**：几乎所有预训练模型（ResNet、VGG 等）训练时都用这套数字。**CNN 分支用的是 ResNet-50，ResNet 官方就是这么归一的。** 用一样的数字，才能和预训练权重"对得上口"。
3. **业界普遍认可**：你随手搜"PyTorch ImageNet normalization"，看到的都是这套。

**归一化到底在做什么？** 公式是：

```
归一化后的值 = (原始值 - mean) / std
```

- `- mean`：把图片亮度"拉平"，让中心落在 0（原来 0~255 的平均值约 127，减去均值后整体居中）。
- `/ std`：把波动范围"缩到 1"（除以标准差后，数据分布的标准差变成 1）。

**效果**：让所有图片的数值都在一个"标准范围"里（大部分在 -1 到 1 之间），模型学起来更快、更稳。

**为什么 CLIP 那边用的是 0.5？** 你看 CLIP 那份用的是 `Normalize([0.5,0.5,0.5],[0.5,0.5,0.5])`——这是 CLIP 自己规定的归一化方式（把 0~255 缩到 -1~1），**跟 ResNet 那套不一样**。这就是为什么同一张图要准备两份、走不同加工：**两个模型（CLIP 和 CNN）要求的输入格式不同。**

**小结：** 这些数字不是代码作者编的，是 ImageNet 的统计值 + 预训练模型的官方要求。**用它们准确、正确、且必须和预训练模型一致**，不要随便改。

---

## 六、第 4 步：打包成一摞（batch），送进模型

单张图太碎，模型喜欢"一批一批"地看。这一步在 `train.py:206-228`：

```python
train_dl = DataLoader(
    train_ds,
    batch_size=BATCH_SIZE,   # config 里是 64，即每次看 64 张
    shuffle=True,            # 训练时打乱顺序
    num_workers=NUM_WORKERS,
)
```

**DataLoader 是什么？** 一个"自动上菜机"。它知道目录（`train_ds`），会：

1. 从目录里取出 64 个样本（对应说明书 64 行）
2. 每个样本都走一遍第 3 步的读图+加工
3. 把 64 个数字块"摞"成一摞，形状变成 `[64, 3, 224, 224]`

这个"一摞 64 张"就叫一个 **batch**。`shuffle=True` 表示每次拿的 64 张都随机换一批，防止模型只记住顺序。

> 一个 batch 形状：`[64, 3, 224, 224]` = 64 张 × 3 层颜色 × 224 高 × 224 宽。

模型就按 batch 一摞一摞地吃，直到把所有训练数据都吃完一遍（这叫"一个 epoch"）。

## 七、第 5 步：模型算猜测（前向传播）

现在，一摞图（`[64,3,224,224]`）送进了 `train.py:287-288` 的训练循环：

```python
for i, batch in enumerate(train_dl):
    raw_inputs = process_batch(batch, model=model)   # ← 先加工成"特征"
    output = transformer_model(raw_inputs)           # ← 再送进模型
```

### 第 5.1 步：process_batch —— 从图里"提炼"特征

`process_batch`（`train.py:66-142`）是个"炼金师"，把一张脸的图片，提炼成模型能理解的各种"精华"。这一步分几个小动作：

**动作一：把图喂给 CLIP，得到"语义向量"**

CLIP 是一个"看图说话"的模型（就是 OpenAI 那个，能理解图片和文字的对应关系）。把脸图喂给它，得到 512 个数字，代表"这张脸在语义上像什么"。

```python
img_feats = model.encoder_i(_input.face)   # 图片 → 512个数字
```

**动作二：让 CLIP 帮忙选"最像的属性"（feature_1 / feature_2 的第一步）**

这一步是整个流程里最巧妙、也最难懂的地方，我拆成三小步慢慢讲。

**前置知识：CLIP 不只能"看"图，还能"懂"文字。**

前面说 CLIP 是"看图说话"的模型。它更厉害的地方在于——**图片和文字可以放到同一个"语言"里比较**。就像你懂中文也懂英文，把一张照片和一段文字放在一起，你能判断"这张照片是不是在说这段文字的内容"。

CLIP 也是这么工作的：它把图片变成一个 512 个数字的向量（`img_feats`），把文字也变成 512 个数字的向量。**两个向量越接近，就说明图片和文字越匹配。**

**现在，代码里提前写好了几组"文字标签"。** 这些标签在 `model/models.py:260-285`：

```python
# 光照：3 种描述
illumination_texts = [
    "a face with bright light",   # 亮光下的脸
    "a face with low light",      # 暗光下的脸
    "a face with shadows",        # 有阴影的脸
]
# 头姿：2 种描述
headpose_texts = [
    "a frontal face",   # 正脸
    "a profile face",   # 侧脸
]
# 背景：2 种描述
background_texts = [
    "a face on bright background",  # 亮背景
    "a face on dark background",    # 暗背景
]
# 视线方向：8 种描述
label_texts = [
    "A photo of a face looking left",        # 往左看
    "A photo of a face looking upper left",  # 往左上
    "A photo of a face looking up",          # 往上看
    ... # 一共 8 个方向
]
```

**这些文字先被翻译成向量，存起来。** 在 `model/models.py:288-312`，代码用 CLIP 的"读字"功能把这些文字变成 512 维向量，并且归一化：

```python
# 用 CLIP 把文字变成向量
self.illum_feats = clip_model.encode_text(illum_tokens)     # [3, 512]  3个光照词的向量
self.head_feats  = clip_model.encode_text(headpose_tokens)  # [2, 512]  2个头部姿势词的向量
self.bg_feats    = clip_model.encode_text(bg_tokens)        # [2, 512]  2个背景词的向量

# 归一化（把长度变成1，只保留"方向"）
self.illum_norm = self.illum_feats / self.illum_feats.norm(dim=-1, keepdim=True)
```

> 这些文字向量是**预计算好、存起来的**，跟训练无关。相当于提前备好的"标准答案标签"。

**现在开始真正的"匹配"。** 回到 `train.py:98-112`：

```python
# ① 把图的向量也归一化
img_norm = img_feats / (img_feats.norm(dim=-1, keepdim=True) + 1e-2)

# ② 图片向量 × 每个文字向量 = "这张脸有多像这个文字"
sim_illum = model.logit_scale.exp() * img_norm @ model.illum_norm.T  # 和3个光照词比
sim_head  = model.logit_scale.exp() * img_norm @ model.head_norm.T   # 和2个头姿词比
sim_bg    = model.logit_scale.exp() * img_norm @ model.bg_norm.T     # 和2个背景词比

# ③ 找出"得分最高"的那个文字
idx_illum = sim_illum.argmax(dim=-1)   # 这张脸最像"亮光"还是"暗光"？
idx_head  = sim_head.argmax(dim=-1)    # 最像"正脸"还是"侧脸"？
idx_bg    = sim_bg.argmax(dim=-1)      # 最像"亮背景"还是"暗背景"？
```

那 `@`（矩阵乘法）是什么意思？其实就是**把两个向量逐项相乘再相加**，算出一个"相似度得分"。两个向量长得越像，这个得分越高。所以：

- `sim_illum` 有 3 个数：这张脸和"亮光"像多少分、和"暗光"像多少分、和"阴影"像多少分
- `argmax` 挑出得分最高的那个 → 比如得分最高的是"亮光"，`idx_illum = 0`

**这就是"让 CLIP 帮我们判断这张脸处于什么光照、什么头姿、什么背景"。**

**动作三：组合出 feature_1 和 feature_2（最核心的加法）**

选好"最像的属性"之后，代码把图片向量和选中的属性向量**相加**：

```python
# train.py:113-123
# 取出"选中"的那个属性向量（比如选中的"亮光"向量）
selected_illum = model.illum_feats[idx_illum]
selected_head  = model.head_feats[idx_head]
selected_bg    = model.bg_feats[idx_bg]
selected_label = label_feats[idx_label]   # 视线方向也选一个

# feature_1 = 图片向量 + 光照 + 头姿 + 背景
feature_1 = img_feats + selected_illum + selected_head + selected_bg
feature_1 = feature_1 / (feature_1.norm(dim=-1, keepdim=True) + 1e-3)  # 再归一化

# feature_2 = 图片向量 + 视线方向
feature_2 = img_feats + selected_label
feature_2 = feature_2 / (feature_2.norm(dim=-1, keepdim=True) + 1e-3)  # 再归一化
```

用人话翻译：

- **feature_1 = 图片本身 + 光照 + 头姿 + 背景**：这四个加起来，描述的是"这张脸长什么样、处在什么环境"——**它是"环境信息"**。
- **feature_2 = 图片本身 + 视线方向**：图片信息加上"往哪看"——**它是"任务信息"**（跟最终要预测的视线最相关）。

**为什么要做加法？** 这是这套方法（借鉴"CLIP 语义先验"的思想）的核心：

- 光靠图片向量，模型不知道"这是什么光照、什么角度"。
- 加上 CLIP 从文字里学来的属性向量，就等于**用 CLIP 已经会的东西（光照、姿势、背景的概念）帮图片"补充说明"**。
- 好比：给模型一张照片，再告诉它"这是一张亮光下的正脸、暗背景"——模型理解得更准确。

**feature_1 和 feature_2 的区别，一句话记牢：**

> `feature_1` = 图片 + **环境**（光照/头姿/背景），回答"这图是什么环境"
> `feature_2` = 图片 + **视线**，回答"这人往哪看"（跟最终任务最贴）

两个特征最后都会喂给 Transformer。区分它们，是为了让模型**分开处理"环境信息"和"任务信息"**，别混在一起。

**动作四：把图喂给 CNN（ResNet），得到"局部细节"**

```python
feature_map = model.main_model(_input.other_face)["features"]
```

CNN 擅长抓"局部纹理"（眼睛轮廓、皱纹等），得到一张"特征地图"，再切成一小块一小块的小 token，叫 `feature_3`。

**动作五：从 CLIP 中间层抓出每个图像小块的 token**

用了一个"钩子"（hook）从 CLIP 中间层偷看每个小块的向量，叫 `token_img_patch`。这是更细的局部信息。

所以一张脸，被提炼出**四个特征**，打包成一个字典 `raw_inputs`：

```python
features = {
    "feature_1": [64, 512],        # 语义 + 光照/头姿/背景
    "feature_2": [64, 512],        # 语义 + 视线方向
    "feature_3": [64, 小格数, 2048],  # CNN 局部细节
    "token_img_patch": [64, 小块数, 768],  # CLIP 中间层细节
    "label": 真值,                 # 标准答案也一起带上
}
```

> 专业术语：这些数字块都叫"特征"（feature）。特征是模型"理解"图片后抽出来的精华。

### 第 5.2 步：transformer_model —— 把特征变成视线方向

`TransformerDeepSeek_gaze`（`model/transformer_models.py`）是真正的大厨。它把上面四个特征全拼在一起，变成一个长长的序列，然后用很多层"注意力"（transformer，就是 GPT 那个"注意力"技术）去理解这些特征之间的关联，最后吐出一个预测：

```python
output = transformer_model(raw_inputs)   # 输出 [64, 3] —— 每个样本的 3 维视线方向
```

看 `transformer_models.py:1059` 的 `forward`：

```python
# 把特征 1、2 变成单个 token，特征 3、patch 变成一串 token
token_f1 = ...  # [64, 1, 768]
token_f2 = ...  # [64, 1, 768]
token_f3 = ...  # [64, 小格数, 768]
token_patch = ...  # [64, 小块数, 768]
# 拼成一个长序列
transformer_input = torch.cat([token_f1, token_f2, token_f3, ...], dim=1)
# 前面加一个特殊的 CLS token（相当于"总结代表"）
transformer_input = torch.cat([cls_tokens, transformer_input], dim=1)
# 经过很多层处理
x = transformer_input
for layer in self.layers:
    x = layer(x)
# 取 CLS token（代表整张脸的理解），回归出 3 个数
out = self.linear_head(x[:, 0, :])   # [64, 3] —— 预测的视线方向
```

**这一步的含义**：让模型"看"完所有的特征后，给出它对"这双眼睛往哪看"的判断——3 个数（预测的视线方向）。

## 八、第 6 步：比一比，算差，然后学习（损失 + 反向传播）

现在模型有了两个东西：

- 它的**预测**（guess）：`[64, 3]` 视线方向
- 说明书给的**真值**（truth）：`label` 也是 `[64, 3]`

模型要学习，就得知道自己"错得有多离谱"。这在 `train.py:290-317`：

```python
loss_gaze = angular_loss(output, label)          # 预测和真值差多少（角度差）
loss_sep  = feature_separation_loss(feature_1, feature_2)  # 辅助损失
loss = loss_gaze + 1.0 * loss_sep               # 总损失

loss.backward()      # 反向传播：算出每个参数该往哪改
optimizer.step()     # 按这个方向更新参数
```

### angular_loss —— 主损失（角度差）

`train.py:154-160`：

```python
def angular_loss(pred, target):
    pred_n = pred / (pred.norm(dim=-1) + 1e-6)      # 归一化预测
    target_n = target / (target.norm(dim=-1) + 1e-6) # 归一化真值
    cos_sim = (pred_n * target_n).sum(dim=-1)        # 算方向多接近
    loss = torch.acos(cos_sim).mean()                # 夹角（弧度）
    return loss
```

**人话**：预测的视线和真实的视线，方向越接近，夹角越小，损失越小。模型的目标就是让这个夹角越来越小（视线越来越准）。

### 反向传播是什么

`loss.backward()` 是一个"问责过程"：损失大，就问"是哪个环节导致猜错了"，把责任（梯度）分摊给每个参数，然后 `optimizer.step()` 按责任大小微调参数。

**反复执行**：每个 batch 猜一次 → 算损失 → 改参数 → 再猜。一个 epoch（把所有训练数据看一遍）结束后，再拿测试集测一下效果，如此循环 `NUM_EPOCHS`（50）次。

## 十、几个"老奶奶友好"的常见疑问

**Q1：模型为什么不直接看原始图片，要这么折腾？**
原始照片是杂乱无章的。模型不擅长处理乱数据，得先变成"整齐的数字块"（张量）、再抽成"精华"（特征），才好学。就像给爷爷喂饭得先捣碎、吹凉。

**Q2：face 和 other_face 是同一个图吗？**
是。同一张脸复制了两份，只是分别用 CLIP 和 CNN 的不同加工方式处理。CLIP 负责"看懂整张脸的意思"，CNN 负责"看清脸上的细节"，各取所长，最后合起来。

**Q3：一个 batch 是什么感觉？**
想象模型一次吃 64 碗饭（64 张脸），吃完算一次账（更新一次参数）。吃完所有碗（一个 epoch），休息一下，用没吃过的菜（测试集）考验它学得咋样。

**Q4：真值（label）从哪来？**
是 Gaze360 数据集的作者提前标好的"标准答案"——他们人工判断每张脸的人往哪看，记录下来。模型训练就是用这个标准答案来"对答案、纠错"。

**Q5：模型怎么知道猜得对不对？**
通过"损失"（loss）这个数字：猜得对，loss 小；猜得错，loss 大。模型拼命让 loss 变小，就是拼命猜得更准。

**Q6：那些 0.485、0.229 的归一化数字，会不会是代码作者乱写的？**
不是。它们来自 ImageNet 数据集（1400 万张图）的统计，是 ResNet 等预训练模型的官方标准配方。因为你的 CNN 分支用的就是 ResNet-50 的预训练权重，所以必须用同一套数字，才能"对上口"。详见第 3.4 层。

**Q7：feature_1 和 feature_2 到底怎么来的？一句话能说清吗？**
能。`feature_1` = 图片向量 + 选出的"光照 + 头姿 + 背景"向量（描述环境）；`feature_2` = 图片向量 + 选出的"视线方向"向量（描述往哪看）。"选出"靠 CLIP 把图片和预设的文字标签比对、挑最像的那个。详见第 5.1 步动作二、动作三。

**Q8：CLIP 凭什么能"选"出光照/头姿？**
因为 CLIP 是"图文对照"模型——图片和文字可以放进同一个向量空间比较。代码预先把"亮光/暗光/正脸/侧脸..."这些文字用 CLIP 变成向量存好，再把图片向量跟它们逐一比相似度，挑最像的。这一步不需要训练，是 CLIP 自带的能力。
