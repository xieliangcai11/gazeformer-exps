## 二、我们在同一口径下的现状

我们把"角度"换算回厘米来对齐论文口径：
验收几何 = 眼睛离屏 30cm（`VIEWING_DISTANCE_CM`）。
在该几何下，屏幕中心偏差 x cm 大致对应角度 θ = atan(x / 30)。
反过来，角度 a° 对应弧长偏差 ≈ 30·tan(a·π/180)。

| 我们的模型（subject 划分） | 平均角度 | 折算屏幕偏差(cm) |
|---|---|---|
| 消融最优 8ep（mse_angle+no_depth... 未跑满） | ~4.56° | ≈ 2.39 cm |
| 最优 30ep（mse_angle+no_depth+unfreeze2） | ~4.38°(ep20, 还在降) | ≈ 2.30 cm |
| 论文 RGBD | — | **1.89 cm** |
| 论文 RGB-only | — | 2.26 cm |

> 折算用近似 arctan：2.30cm ↔ 4.38°（tan⁻¹(2.30/30)=4.38°，一致）。

**结论**：我们 30ep 的 ~2.30cm 已非常接近论文 RGB-only 的 2.26cm，
距离论文 RGBD 1.89cm 还差 ~0.4cm（≈22%）。这个差距是真实的、可以追的。

## 三、为什么论文能做到 1.89cm？—— 它的三个结构性优势

### 优势 1：跨数据集迁移（最大差距来源）
论文明确写了：**RGB 分支先用 GazeCapture（174 万样本级）预训练，再在我们数据上微调**
（4.2 节："The RGB part of the model is first trained with the GazeCapture dataset"）。
这意味着它的 RGB 分支带着海量"人眼看手机屏幕"的先验来到这个 16 万样本的小任务上。

**我们目前**：DINOv2 是通用自监督特征，**从未见过"注视"这个任务**；
冻结 + 只训融合头，等于零注视先验。这是我们与论文最大的结构性差距。

### 优势 2：注意力显式加权眼区
论文的网络是 **spatial attention CNN**（AlexNet 特征 + 1×1 conv 生成空间权重图），
并且他们的可视化明确显示：RGB 注意力集中在双眼，深度注意力集中在脸部中央/边缘（=头姿）。
这等价于告诉模型"该看哪里"。我们当前的 transformer 融合虽然有注意力，
但没有任何显式的"眼区增强"或位置编码，等于把"找眼睛"这个难题完全丢给模型自学。

### 优势 3：输入分辨率 448×448（我们是 224×224）
论文输入 448×448 的裁剪脸。眼睛区域（尤其虹膜）在高分辨率下才可分辨。
我们在 224 下，双眼虹膜只有几个像素，这是硬性信息损失。

## 四、对应的三条改进路线（按收益/成本排序）

### 路线 A：跨数据集预训练 RGB 分支（对齐论文优势 1）——预期收益最大
两条实现路径：
- **A1（低成本）**：用**公开预训练注视模型**（在 GazeCapture/Eth-XGaze 等上训练过的开源权重）
  作为 RGB 分支的初始化，再在我们数据上微调。开源可得的包括 gaze estimation 社区的
  RT-Gene / Gaze360 / ETH-XGaze / MPIIGaze 预训练权重，或 iTracker 复现权重。
- **A2（中成本）**：用我们的数据先做"注视相关自监督/有监督预训练"不可行（数据就这一份），
  所以 A1 是唯一现实路径。

**风险**：外部权重可能与我们的输入分布（近距离、躺/走/站）有 gap，但微调可吸收。
**这就是"结合过往知识"的正确用法：不是自己从零学注视，而是把社区的注视先验搬进来。**

### 路线 B：显式眼区增强（对齐论文优势 2）
两条实现路径：
- **B1（低成本）**：对 RGB 特征图加**空间注意力模块**（论文同款思路：1×1 conv 出 weight map），
  让模型自己学"往哪儿看"。不加新输入，纯模块级改动。
- **B2（中成本）**：引入**人脸关键点/眼部检测**，显式裁出双眼区域作为额外 token。
  你问的"眼睛 bbox 从哪来"正是这条路——回答是：**数据集没有提供眼部 bbox**，
  但我们有两个获取途径：
  1. 用开源 landmark 模型（mediapipe FaceMesh / dlib 68 点 / InsightFace）**离线推理**出眼部位置，
     把它作为**预处理产物**存进 index（可复现、可开源、不依赖在线检测）；
  2. 你提的"目标检测层"：训练一个眼区检测头。可行，但它是"用模型学模型"，
     需要额外标注或弱监督，**第一轮不建议**（收益不确定、成本高）。
- **泛化性问题（你问的对）**：如果线上/新场景没有眼部 bbox，
  B1（学出来的注意力）天然泛化更好；B2 的离线 landmark 也只是预处理，任何部署环境都能跑同一个模型，
  不构成泛化障碍——真正的泛化风险是 landmark 模型在极端姿态（躺/走）下检测失败，
  这可以用"检测失败时回退到全脸 crop"来兜底。

### 路线 C：分辨率 224 → 448（对齐论文优势 3）
- 直接收益：虹膜细节可见。
- 代价：显存/算力 ~4×；DINOv2 patch 数从 256 → 1024，融合开销上升。
- 建议：**第二轮再做**，先在 224 下把路线 A/B 吃干净。

## 五、关于深度分支（回应"我相信深度有更多信息"）

你的直觉有论文背书：原文 RGB 2.26 → RGBD 1.89（**-16.3%**），深度确实有价值。
我们消融显示逆深度单通道无效（5.15° vs 4.92°），原因不是"深度没用"，而是**我们把它用错了**：

1. **信息量**：我们只有 ~169 级灰度 JPEG，逆深度 1/(z+ε) 又放大了近处噪声，
   8×8 池化后每格只剩 1 个标量 → 一个 Linear(1→384) 投影，几乎等于"给模型看 64 个数字"。
2. **对齐**：depth 与 RGB 分辨率不同（640×480 vs 1440×1080），bbox 按比例缩放存在累计错位风险。
3. **用法**：论文用的是**双流 CNN + 空间注意力乘法融合**（feature-map 级相乘），
   保留了空间结构；我们是把深度压成 64 个 token 扔进 transformer，空间细节已经没了。

**正确的深度用法（如果要做）**：
- **保留空间结构**：depth 也走一个 CNN/ViT 分支，输出 feature map（不是压成 token），
  再与 RGB feature map 做**空间注意力乘法融合**（论文原方案）。
- **或提升深度质量**：用预训练单目深度模型（Depth Anything V2 / Metric3D / ZoeDepth）从 RGB 重生成高质量深度，
  替代原始低质量 depth 图——这是 2023-2026 的成熟做法，能绕开"169 级灰度"的信息瓶颈。
- 建议作为第二轮，先把路线 A（注视先验）吃掉，那是最大的坑。
