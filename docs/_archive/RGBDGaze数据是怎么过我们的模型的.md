# RGBDGaze 数据集是怎么过我们这个模型的？

> 这篇文章把"RGBDGaze 数据"从头到尾、一步一步讲清楚：
> 数据长什么样 → 我们怎么把它喂给模型 → 模型内部怎么处理 → 最后算出什么。
> 用最日常的比喻，不装专业术语。你看完就能明白整个来龙去脉。

---

## 一、一句话先总览

**RGBDGaze 数据 = 一堆"人脸照片 + 深度照片 + 说明文字"，我们的任务 = 看这两张照片，猜这个人盯着手机屏幕上的哪个点。**

就像：
> 你拿着一张别人的照片（脸）和一张"距离照片"（深度），然后猜"这个人正盯着他手屏幕上哪个位置"。

下面一步步拆开。

---

## 二、原始数据里有什么？

RGBDGaze 的原始数据存在一个多层的文件夹里：

```
RGBDGaze_dataset/
├── p1/  p2/  ...  p45/        ← 45 个人（第几个被试）
│   └── decoded/
│       ├── sitting/           ← 坐着玩手机
│       │   ├── rgb/0.jpg      ← 彩色照片（人脸近照）
│       │   ├── depth/0.jpg    ← 深度照片（谁离得远谁离得近）
│       │   └── label.csv      ← 说明：这一刻这个人盯哪
│       ├── standing/          ← 站着
│       ├── walking/           ← 走路
│       └── lying/             ← 躺着
├── iphone_spec.csv            ← 每种 iPhone 的屏幕尺寸表
├── intrinsic.json             ← 相机参数（每台手机）
└── README.txt
```

关键信息都在 **label.csv** 里，每一行对应一帧（一张照片+一张深度图），写着：

| 字段 | 人话 |
|---|---|
| `bbox_x, bbox_y, bbox_w, bbox_h` | **人脸在哪**（框的位置和大小） |
| `gt_x_pt, gt_y_pt` | **真人盯着屏幕的哪个点**（标准答案） |
| `device` | 用的哪款 iPhone |
| `imu_x, imu_y, imu_z` | 手机姿势（重力感应） |

**所以：数据 = 照片 + 深度图 + 一份"这是哪个人盯着哪"的说明书。**

---

## 三、第一步：我们先把"说明书"整理成一张大表（预处理）

原始数据太零散（45 个人 × 4 种姿势 × 很多帧），直接给模型不方便。

我们写了一个小程序 `rgbdgaze_preprocess.py`，它做的事情是：

1. 把 45 个人、4 种姿势的所有记录扫一遍
2. 每一条记录生成一行，写进一张统一的大表 `index.csv`
3. 顺便查出每种 iPhone 的屏幕尺寸、每像素对应多少厘米——写进表里备用
4. 把 14 万条记录按"训练 / 验证 / 测试"分成三堆（给各自的清单文件）

**这一大步不碰照片，只是把"说明书"整理好、分组好。** 结果类似：

```
rgb_path, depth_path, bbox_x, bbox_y, ..., device, screen_w, screen_h,
gaze_x, gaze_y, cm_px_x, cm_px_y, subject, activity
```

每一行 = 一个样本（一张脸 + 一张深度图 + 一堆标记）。

---

## 四、第二步：模型"吃饭"——数据集类把照片和标记配成对

`index.csv` 只是表，模型要吃的是"图片 + 答案"。
我们写了一个"数据集类" `RGBDGazeDataset`，它的任务是：**给定一个编号，取出对应的照片、深度图，和标准答案，配成一份"饭"。**

它对每个样本做这些事：

1. **照着人脸框，把脸裁出来。**
   - 读彩色照片 `rgb`，按 `bbox` 把脸那一小块裁出来
   - 读深度图 `depth`，按**同一位置**把对应的深度区域裁出来
   - 注意：彩色图是 1440 宽，深度图是 640 宽，两者分辨率不一样，所以要按比例把"人脸框"缩放一下再裁（不然位置对不上）

2. **把裁出来的两小块图都变成 224×224 的标准大小**（模型喜欢吃固定尺寸的饭）。

3. **把标准答案（真人盯着屏幕的点）归一化**：
   - 屏幕坐标（比如 x=50）除以屏幕宽度（比如 428）→ 得到 0~1 之间的数
   - 这样不管什么手机，答案都在 0~1 之间，模型好处理。

4. **返回三样东西**：
   - `face`（彩色脸的"数字版"）
   - `other_face`（深度信息的"数字版"，柱子类存变）
   - `label`（0~1 之间的标准答案）

> 小比喻：数据集类就像一个"配餐员"，每次按编号把一人份的"饭"（两小盘图 + 标准答案）端出来。

---

## 五、第三步：模型"动脑子"——两个流分别读两盘饭

我们建的模型叫 **RGBDGaze 双流模型**（`RGBDGazeModel`）。名字"双流"= 它有两条信息通道，分别处理两盘不同的饭。

```
        ┌─────────────────────────────────────┐
        │          RGBDGazeModel (模型)          │
        │                                     │
彩色人脸 ─▶ 通道A：CLIP 看懂脸的"意思"         │
(face)  │         （肤色、五官、表情、大概朝哪）   │
        │                                     │
深度人脸 ─▶ 通道B：ResNet 看懂脸的"距离"       │
(depth) │         （脸离相机多近、脸部起伏）     │
        │                                     │
        └──────────┬──────────────────────────┘
                   ▼
              合并成一个 512+512+2048 的数字串
                   ▼
              最后一小层：算出 2 个数 = 屏幕横坐标 + 屏幕纵坐标（0~1）
```

### 通道 A：CLIP（看"意思"）

- 把彩色人脸切成 224×224
- 用 CLIP（一个很会"看图说话"的模型）把它变成一个 512 个数字的"特征"
- 这 512 个数字，大致代表"这张脸长什么样、大概往哪看"

### 通道 B：ResNet（看"距离"）

- 把深度人脸也处理
- 用 ResNet（一个擅长抓细节的模型）提取局部特征图，再压缩成一个 2048 个数字的"特征"
- 这 2048 个数字，大致代表"这张脸的三维起伏、离相机多远"

### 合并 + 出结果

- 把 A 的 512 + 512（两个）和 B 的 2048，拼成一个长数字串
- 送进最后几层"全连接层"，输出 **2 个数**
- 这就是模型猜的"注视点"：(屏幕横坐标, 屏幕纵坐标)，都是 0~1

---

## 六、第四步：怎么算"猜得准不准"（一个逐步进化的尺子）

模型猜出了屏幕上的点，要和真人的标准答案比。误差的"尺子"我们一步步升级：

### 尺子1：L2 误差（一开始）
```
误差 = 猜的点 和 真实点 的直线距离（在0~1空间）
```
- 数字是 0~1 之间的小数
- **缺点：看不出好坏**（0.2 是好是坏？不知道，因为每个手机屏幕大小不同）

### 尺子2：厘米误差（后来加的）
```
误差(厘米) = 误差(0~1) × 屏幕像素 × 每像素多少厘米
```
- 用 `iphone_spec.csv` 查出每台 iPhone 的屏幕物理尺寸
- 把 0~1 误差换算成屏幕上的"实际厘米"
- **这下能想象了**：2.3 厘米大概比硬币大一点

### 尺子3：角度误差（你要求的方向）
```
每个点 → 视线方向（眼睛在屏幕前30cm）
角度误差 = 预测视线方向 与 真实视线方向 的夹角（度）
```
- 你的规格给了"正视 30cm"，正好当"尺子"
- 详见另一篇《为什么现在能算角度误差.md》

## 七、整个流程一张图（老奶奶版）

```
⚠️ 这些是"原始材料"
  RGBDGaze_dataset/
  ├── 45 人 × 4 姿势
  │   ├── rgb/*.jpg      彩色照片
  │   ├── depth/*.jpg    深度照片
  │   └── label.csv      说明（人盯哪、人脸框、手机型号）
  └── iphone_spec.csv    每种手机的屏幕尺寸

   ▼  ① 预处理 (rgbdgaze_preprocess.py)
  整理 + 分组 → index.csv + train/val/test 清单
   （14 万条，按训练/验证/测试分堆）

   ▼  ② 数据集类 (RGBDGazeDataset)
  按编号取出 → 裁脸 → 归一化 → 端出 (face, other_face, label)

   ▼  ③ 模型 (RGBDGazeModel)  —— 双流
  face  → CLIP 看懂"脸的意思"
  depth → ResNet 看懂"脸的距离"
          合并 → 输出 (预测的横坐标, 预测的纵坐标)

   ▼  ④ 打分 (在 train_rgbdgaze.py 里)
  和标准答案比
  → L2 / 厘米 / 角度误差
  → 报告平均误差 + 95%误差
```

## 八、你问的几个关键点，直接回答

**Q1：模型到底看几张图？**
每帧看**两张**：一张彩色脸 + 一张深度脸。所以叫"RGB（彩色）+ Depth（深度）双流"。

**Q2：为什么深度也要看？**
因为深度能告诉模型"人脸离相机多远、脸的三维形状"——这是彩照看不出来的。论文里光用彩照误差 2.26cm，加上深度能降到 1.89cm。

**Q3：模型输出的是什么？**
**两个数字**：屏幕横坐标 + 屏幕纵坐标（都归一到 0~1）。它不直接输出"角度"，角度是后面拿"距离30cm"把坐标换算出来的。

**Q4：人脸框从哪来？**
直接写在 `label.csv` 里（数据集的作者已经用苹果的人脸检测标好人脸框了）。我们只是照着框裁出来，不用自己再找脸。

**Q5：14 万个样本大概什么量级？**
很大。能撑得起一个模型的训练。分成训练 11.4万 / 验证 1.4万 / 测试 1.4万。

**Q6：它和 Gaze360 的区别？**
- Gaze360：模型输出"3D 视线方向"（角度），数据标注就是方向。
- RGBDGaze：模型输出"屏幕上的点"（2D），数据标注是点。
- 所以一个用角度误差，一个用"点到点的距离/角度"——这是两套不同的任务设定。

---

## 九、总结（三句话）

1. **RGBDGaze 数据** = 彩色脸 + 深度脸 + 一份"人盯屏幕哪个点"的说明书。
2. **我们的模型** = 两条通道分别读彩色脸（CLIP）和深度脸（ResNet），合并后算出"屏幕上的点"。
3. **好不好** = 拿预测点和真实点比，用 L2 → 厘米 → 角度（配合你给的 30cm）逐步换算成能看懂、能对着要求的指标。
