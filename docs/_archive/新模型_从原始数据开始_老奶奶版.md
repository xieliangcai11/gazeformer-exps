# 我们的新模型 —— 从最原始的数据说起（老奶奶版）

> 这一篇把"我们到底要做一个什么样的模型"从头到尾讲清楚。
> 从最原始的数据开始，一步一步走到最后模型输出什么、怎么训练、怎么算准不准。
> 全部用大白话 + 画图，不装术语。你看完就能明白我们要造什么。

---

## 〇、一句话总览

**我们有一堆"人脸彩色照片 + 人脸深度照片"，任务是：让模型看一眼这两张照片，猜出这个人正盯着手机屏幕上的哪个点。**

新模型和平常不一样的地方是"两只眼睛"都更聪明了：

- 彩色照片：交给一个叫 **DINOv2** 的厉害模型，它能看懂"脸往哪边扭、大致朝哪看"；
- 深度照片：我们不把它当普通图片看了，而是先把**每一点的远近**算成"离得越远数越小"的**逆深度数字**，让模型真正用上"脸离屏幕多远、鼻梁比脸颊近多少"这些几何信息；
- 最后把两者的信息**交叉融合**（你来我往地互相参考），一起猜出一个点。

---

## 一、原始数据里到底有什么？

先看最原始的材料，它长这样（一层套一层）：

```
RGBDGaze_dataset/
├── p1/  p2/  ...  p45/          ← 45 个人（第几个被测者）
│   └── decoded/
│       ├── sitting/             ← 坐着玩手机
│       │   ├── rgb/0.jpg        ← 彩色照片（人脸近照）
│       │   ├── depth/0.jpg      ← 深度照片（暗的远、亮的近）
│       │   └── label.csv        ← 说明书：这人看屏幕哪个点
│       ├── standing/            ← 站着
│       ├── walking/             ← 走路
│       └── lying/               ← 躺着
├── iphone_spec.csv              ← 每种 iPhone 的屏幕尺寸表
├── intrinsic.json               ← 相机参数（镜头焦距、画面中心）
└── README.txt
```

关键信息都在 **label.csv** 里，一行对应一帧（1 张彩色 + 1 张深度 + 1 行说明）：

| 字段 | 人话 |
|---|---|
| `bbox_x, bbox_y, bbox_w, bbox_h` | **人脸在哪**（框住脸的框） |
| `gt_x_pt, gt_y_pt` | **真人正盯着屏幕的哪个点**（标准答案） |
| `device` | 用的哪款 iPhone |
| `imu_x, imu_y, imu_z` | 手机姿势（重力的方向，很少用） |

**一句话**：原始数据 = 彩色脸 + 深度脸 + 一本"他看哪"的说明书。

> **我们实测确认**：这里存下来的深度图是 640×480、压缩成"灰白深浅"的图片，全图只有大约 169 个深浅等级。也就是说，它已经把"距离"损失得很粗糙，不能直接当精确的米数用。这是后面所有设计的边界。

## 二、第一步：把说明书整理成一张大表（预处理）

原始数据太零散（45 人 × 4 姿势 × 很多帧），直接给模型不方便。我们写了一个小程序
`rgbdgaze_preprocess.py` 做这些：

1. 把 45 人、4 种姿势的所有记录扫一遍；
2. 按 device 查清楚每种 iPhone 的屏幕物理尺寸（用于误差换算）；
3. 把每一条记录压成一行，写进一张统一大表 `index.csv`；
4. 把 14 万条记录按"训练 / 验证 / 测试"三堆分好。

**这一步不碰照片本身，只是把说明书整理好、排好队。**

---

## 三、第二步：数据"吃饭"——把照片和标准答案配成对

模型要吃的是"图片 + 答案"。`RGBDGazeDataset`（数据集类）的任务：**给定一个编号，取出对应的照片、深度图和标准答案，配成一份饭。**

它做这些：

1. **照人脸框，把脸裁出来。** 彩色图宽 1440、深度图宽 640，两图分辨率不一样，所以要按比例把人脸框缩放好再裁（不然嘴对不上）。

2. **把裁出来的两小块都变成 224×224 标准大小**（模型喜欢吃固定尺寸）。

3. **把标准答案归一化**：屏幕坐标除以屏幕宽高 → 变成 0~1 之间的数，什么手机都一样。

4. **返回三样东西**：
   - `face`（彩色脸的"数字版"）
   - `other_face`（深度信息的"数字版"）
   - `label`（0~1 的标准答案）

> 小比喻：数据集类就像一个"配餐员"，每次按编号端出一人份（两小盘图 + 标准答案）。

---

## 四、第三步：新模型"动脑子"——两只更聪明的眼睛 + 交叉融合

我们这次要建的模型，**不会用原来那套 CLIP + ResNet**，而是全新的设计。因为它要解决的问题变了，原来的方法不够用。

```
        ┌─────────────────────────────────────────────┐
        │          新模型（两支 + 融合）                   │
        │                                             │
彩色人脸 ─▶ 分支A：DINOv2 看懂"脸往哪看"                │
(face)  │   （冻结不动，把它当作超强的"眼睛"）              │
        │                                             │
深度人脸 ─▶ 分支B：逆深度 → 看懂"脸离多远、脸面怎么起伏"    │
(depth) │   （把深浅换算成"逆深度数字"，直接喂几何）            │
        │                                             │
        └─────────────┬───────────────────────────────┘
                      ▼
            交叉注意力融合（你中有我、我中有你参考）
                      ▼
              一个汇总标记(CLS)读出全貌
                      ▼
              最后输出 2 个数 = 屏幕横坐标 + 纵坐标（0~1）
```

### 分支A：DINOv2 —— 看懂彩色脸（这是主角）

- 彩色脸切成小方块（patch），喂给 **DINOv2**。
- DINOv2 是 2023 年一个非常强的"看图模型"，我们把它的参数**冻结**（不训练，当作现成的超级眼睛）。
- 它输出两类东西：
  - 一个**汇总标记**（CLS）：整张脸"大概什么意思"；
  - 一串**小方块标记**（patch tokens）：每个小区域各自什么样子。
- 彩色是主角，所以这一支信息量最大。

### 分支B：深度 —— 逆深度单通道，别再涂成彩色图（修掉原来的浪费）

- **原来**（旧模型）：把深度图硬涂成彩色（只有 ~169 个深浅等级），再喂给 ResNet 当普通图片看——它看到的是"颜色"，不是"距离"。
- **现在（更合理）**：把深浅等级换算成**逆深度**（`1/深度`，离得越近数越大），只用 **1 个通道**。网络直接吃"谁近谁远"的数字。
- **而且不放任何"小型网络/模块"**：我们不做 ResNet、不做小 CNN。而是把它当成和彩色一样的一串小方块（patch），拼在彩色旁边，交给同一个注意力融合去"你来我往"。
- **它为什么不喧宾夺主**：因为做的是"睁眼看屏幕"这种近距离任务，模型主要靠彩色脸（已经够亮），深度只是补一点"脸面歪没歪"的信息。所以深度只占一小部分，颜色始终是主角。

> 一句话：彩色脸用当今最强的 DINOv2（冻结当眼睛）；深度只补一点几何（逆深度单通道），不喧宾夺主。

## 五、第四步：怎么算"猜得准不准"——先猜点，再看角度

模型猜出屏幕上的一个点（两个 0~1 的数）。和真人的标准答案比：

- **坐标上的差**：预测点与真实点在 0~1 空间里的直线距离（这个在训练时最方便直接用）。
- **再换算成"视线偏了几度"**：还记得吗？我们有一个固定假设"眼睛在屏幕前 **30cm**"，加上它，一个屏幕上的点就能变成一条"视线方向"，两个方向之间就有一个**夹角（单位是度）**。

这就是你常听说的"角度误差"——它才是你验收规则强调的指标（你这个规格要求"95% 的样本误差 ≤ 1.91°"）。

---

## 六、尾声：一句话收住

我们这次要造的东西，用三句话就能说清：

1. **量一把数据**：彩色脸 + 深度脸，配一本"人看哪"的说明书，已经整理好（14 万条）。
2. **两只更聪明的眼睛**：彩色脸交给冻结的超级看图模型 DINOv2；深度只算成"逆深度单通道"，不再涂成彩色图浪费，也不需要额外的小网络。
3. **一只手融合 + 一把尺子**：两者交叉融合后输出屏幕上的点；训练和验收都用"角度"这把尺子（配合眼睛离屏幕 30cm）。
